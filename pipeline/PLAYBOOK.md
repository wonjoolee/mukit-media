MUKIT MAGAZINE(@mukitmag) — "PRO AUDIO · MI · INSTRUMENTS / 귀와 손으로 고른 장비, 직접 듣고 만져 본 소리를 소개합니다."

## 하루 일과 (예약 작업이 매일 05:50 KST에 실행)
0. **어제 게시 점검(운영자 지시, 2026-11-05):** 어제 날짜 `queue/YYYY-MM-DD/slot*/`에서 `posted.json`이 없는 슬롯(= 빠진 게시)과 `reel_error`·`story_error`가 있는 슬롯을 찾아 오늘 보고 맨 앞에 한 줄로 적는다("어제 5개 중 N개 게시, 빠짐: 슬롯x"). 빠진 기사는 다시 올리지 않는다.
1. 오늘 날짜(KST)를 확인한다. `queue/PAUSE`가 있으면 아무것도 만들지 않고 종료.
2. 기사 후보를 찾는다(아래 출처). 최근 7일 안의 소식 우선. 이미 다룬 주제는 `queue/` 과거 폴더와 `pipeline/LOG.md`로 확인해 중복 금지.
3. **하루 5개**를 만든다(운영자 지시, 2026-11-03). 슬롯1·2·3은 카드 6장 + 릴스 + 스토리, **슬롯4(10:00)·슬롯5(18:00)는 '단신'**(카드 1~2장 + 스토리 이미지, 릴스 없음). 분야는 한 날 안에서 섞는다.
   - 슬롯1(07:50 출근길): 신제품 — 신스·건반·기타·이펙터·오디오 인터페이스·마이크·모니터 등
   - 슬롯2(12:30 점심): 업계·현장 소식 — 프로오디오(공연장·투어·설치), 브랜드 소식, 박람회(NAMM, ISE, Superbooth 등), 펌웨어·소프트웨어 업데이트
   - 슬롯3(21:30 퇴근 후): 생각할 거리 — 명기·역사·기술 해설, 아티스트와 장비 이야기, 홈스튜디오 팁
   - **[GUIDE] 정보 공유 — 3일에 한 번은 반드시(운영자 지시, 2026-11-03).** 아래 'GUIDE 규칙'을 먼저 확인하고, 해당하는 날은 슬롯3(없으면 슬롯2)을 GUIDE로 채운다. 신제품만 보여 주는 매거진이 되지 않게 하는 것이 목적이다.
4. 각 기사마다 `queue/YYYY-MM-DD/slotN/`에 아래를 만든다:
   - 카드 6장 `01.jpg`~`06.jpg` (1080×1350): html을 세션 임시 폴더에 쓰고 `node pipeline/render.js <html> <slot폴더>` → `python3 pipeline/to_jpg.py <slot폴더>`
   - 릴스 `reel.mp4`: `python3 pipeline/reel.py <slot폴더> <slot폴더>/reel.mp4` (카드로 만든 14~16초 영상, 로고 엔딩, 무음)
   - `post.json`: `{"caption": "...", "reel_caption": "...", "tags": [{"username":"...","x":0.5,"y":0.5}]}`
   - 작업용 html은 저장소에 넣지 않는다(결과물만).
5. 미리보기(`/tmp/mukit_preview/…jpg`)와 릴스 한 프레임을 반드시 눈으로 확인한 뒤 커밋·푸시한다. 글자 넘침, 루페 위치, 겹침을 고친다. 푸시는 그날 07:30 KST 전까지.
6. `pipeline/LOG.md`에 한 줄씩 추가: 날짜 | 슬롯 | KIT | 제목 | 출처.
7. 게시는 GitHub Actions(`.github/workflows/publish.yml`)가 07:30/10:00/12:10/18:00/21:00 KST에 자동으로 한다(SANKIT과 같은 시각, 정시 예약 작업이 실행)(슬롯 1/4/2/5/3). 세션이 직접 게시하지 않는다.
8. 마지막에 사용자에게 오늘 5개 요약(슬롯·게시 시간·KIT·제목·출처 링크)을 한국어로 짧게 보고한다. GUIDE가 있었으면 표시하고, 없었으면 다음 GUIDE 예정일을 한 줄로 알린다.

## THIS WEEK — 뮤킷이 제안하는 이번 주 공연 (매주 월요일, 고정 코너)
- **언제:** 매주 **월요일 슬롯2(12:30)**. 그 주 화~다음 주 월요일 공연을 다룬다. 이 날은 GUIDE로 친다(LOG 제목 앞에 `[GUIDE][WEEK]`).
- **무엇을:** 3~4편. 반드시 섞는다.
  - 내한 공연(클래식·팝·재즈·록 무엇이든) 1편 이상
  - 서울 밖 지역 공연 1편 이상: 지역 예술의전당·문화예술회관·아트센터(고양아람누리, 광주예술의전당, 부산콘서트홀, 대구콘서트하우스, 통영국제음악당, 아트센터인천 등), 지역 페스티벌(자라섬 같은 계절 페스티벌)
  - 나머지는 오페라·국악·인디·재즈 등에서 장르를 겹치지 않게
- **사실 확인:** 날짜·시간·장소·가격대·예매처를 공연장 공식 페이지나 공식 예매처(NOL티켓, 예스24, 티켓링크, 멜론티켓, 세종문화티켓 등)에서 확인한다. 확인 못 한 시간은 쓰지 않는다. 초대 전용 회차·매진 회차는 빼거나 '매진'으로 밝힌다.
- **카드 6장:** 기준 예시 `pipeline/assets/example_thisweek.html`.
  - 01 표지: 7일 달력(공연 있는 날에 점), 가장 많이 겹친 날을 루페로 확대 + "뮤킷이 제안하는 이번 주 공연"
  - 02~04 PICK 01~03: 왜 가야 하는지 2~3문장 + 정보 표(DATE·VENUE·PROGRAM/CAST·PRICE). 4편이면 04에 PICK 03·04를 함께.
  - 05 알아 둘 숫자(어두운 카드): 이번 주 공연들 사이의 연결점이나 숫자 하나(예: 같은 날 라흐마니노프 3번과 2번)
  - 06 MUKIT GUIDE: 한눈에 보는 표 + MUKIT NOTE(누구에게 어떤 공연을 권하는지 한 줄) + SOURCE + "잔여석·시간은 예매처에서 다시 확인하세요."
- 상단 오른쪽은 `THIS WEEK`, 하단은 `GUIDE / THIS WEEK` 등. 아티스트 사진·포스터 금지. 협찬·초대권 공연 금지.
- 캡션: `THIS WEEK · MM.DD – MM.DD` / 한 줄 / PICK별 일정·장소·가격·예매처 / 연결점 한 줄 / 확인 안내 / Source / 해시태그(#MUKIT #뮤킷 #이번주공연 포함).

## GUIDE 규칙 (정보 공유, 3일에 한 번 이상)
- **언제:** `pipeline/LOG.md`에서 제목 앞에 `[GUIDE]`가 붙은 마지막 줄의 날짜를 본다. 오늘이 그 날짜로부터 3일째 이상이면(예: 11/3에 GUIDE → 11/6에는 반드시) 오늘 하나를 GUIDE로 만든다. 한 번도 없으면 오늘 만든다. 좋은 소재가 있으면 더 자주 해도 된다(하루 최대 1개).
- **무엇을:** 독자가 "지금 알아야 가서 볼 수 있는" 정보. 주제를 돌려 가며 고른다.
  - 꼭 가 봐야 할 내한공연(해외 아티스트 한국 공연)
  - 클래식 공연(내한 오케스트라·리사이틀, 국내 주요 공연)
  - 계절에 맞는 국내 페스티벌(재즈·록·일렉트로닉·월드뮤직 등)
  - 생각보다 가까운 일본 페스티벌·공연(서울에서 이동 시간·항공 거리 감각 포함)
  - 그 밖에 음악 박람회 관람 정보, 무료 공연·전시(사운드 아트 등), 예매 오픈 소식
- **시점:** 공연일이 오늘로부터 1주~3개월 사이인 것, 또는 예매 오픈이 2주 안에 있는 것을 우선한다. 이미 매진·종료된 것은 쓰지 않는다(매진이면 그 사실을 분명히 적거나 다른 소재로).
- **사실 확인(필수):** 날짜·장소·예매처·예매 오픈 시각·가격대는 주최사/공연장/공식 예매처(인터파크·NOL티켓, 예스24, 멜론티켓, 티켓링크, 예술의전당·롯데콘서트홀 등) 또는 페스티벌 공식 사이트에서 확인한다. 확인 못 한 항목은 "미정/미공개". 일본 공연은 공식 사이트 + 일본 예매처(ぴあ, e+, ローチケ 등)로 확인하고, 엔화 가격은 엔화 그대로 적는다(환산 금지).
- **카드 구성(6장, 같은 루페 형식):** 01 표지(루페로 날짜·도시·숫자 하나를 확대 + 제목) / 02 왜 지금 가야 하나 / 03 무엇을 들을 수 있나(라인업·프로그램) / 04 가는 법(장소·이동·일본이면 항공 시간 감각) / 05 알아 둘 숫자(어두운 카드: 가격대·예매 오픈·남은 일수 등) / 06 MUKIT GUIDE(일정·장소·예매처 표 + SOURCE). 하단 분야 표기는 `GUIDE / 공연`, `GUIDE / 페스티벌` 등.
- **이미지:** 아티스트·인물 사진은 쓰지 않는다. 포스터·공식 키비주얼도 쓰지 않는다. 글자·루페 카드로만 만든다.
- **글쓰기:** 홍보 문구 받아쓰기 금지. 06에 관점 한 줄("누구에게 추천하는가 / 어떤 귀로 들으면 좋은가"). 공연 품질을 단정하거나 아티스트를 깎아내리지 않는다.
- **태그:** 주최사·공연장·페스티벌의 공식 인스타그램을 공식 홈페이지 링크로 확인한 경우만 태그. 아티스트 개인 계정은 태그하지 않는다.
- **LOG 기록:** 제목 앞에 `[GUIDE]`를 붙인다. 예: `2026-11-06 | 3 | 010 | [GUIDE] 겨울에 가볼 만한 일본 재즈 페스티벌 | 공식 사이트 URL`.
- 협찬·초대권 제공 공연은 자동 운영에서 다루지 않는다.

## 품질 기준 (운영자 지시, 2026-11-05) — 모든 기사에 적용
1. **첫 장 훅:** 01 카드에 강한 한 문장이나 질문. 훅도 사실이어야 한다 — 확인 못 한 주장("현장에서 제일 많이 쓰는" 등)은 쓰지 않고, 출처 있는 숫자·질문·대비로 만든다.
2. **숫자와 비교:** "가볍다·조용하다" 대신 "이전 모델보다 0.6kg 가벼움", "자체 잡음 -3dB"처럼. 비교 숫자는 제조사 사양·측정 리뷰 등 출처가 있을 때만. 최상급 표현은 비교 대상과 확인일을 적을 수 있을 때만. 민감 브랜드 비교 금지 규칙은 그대로 지킨다.
3. **마지막 장 CTA:** 마지막 카드와 캡션 끝에 한 줄. GUIDE → "저장해 두고 작업할 때 꺼내 보세요", THIS WEEK → "갈 공연 있으면 댓글로", 제품 기사 → "써 본 분 계신가요? 댓글로". 같은 문장을 연달아 쓰지 않는다.
4. **단신 '한 줄 해석':** 단신 01 카드와 캡션에 `MUKIT 한 줄:` 로 시작하는 해석 한 문장을 반드시 넣는다.
5. **훅 테스트:** post.json에 `"type"`(product/news/brief/guide/thisweek/owner)과 `"hook"`(question/number/contrast/statement)을 기록한다. 같은 type 안에서 날짜가 홀수면 question, 짝수면 number 훅을 우선. 반응은 게시 때마다 `pipeline/stats.csv`에 자동 기록되고, 매주 월요일 제작 보고 끝에 지난주 훅 유형별 평균 좋아요·댓글을 한 줄로 덧붙인다.
6. **운영자 콘텐츠 시간 시험:** 시간을 정하지 않은 운영자 콘텐츠는 11/9 주 12:10(슬롯2), 11/16 주 21:00(슬롯3) 자리에 넣고 이후 반응 좋은 쪽을 기본으로 한다.

## 이미지 — 사진 우선 (운영자 지시, 2026-11-05)
운영자 피드백: "산킷에 비해 이미지가 적고 콘텐츠가 부실하다." 글자·루페만으로 된 카드는 더 이상 기본이 아니다.

- 보도용 사진은 원본 비율 그대로(자르기·확대·사진 위 글자/선/원 금지), 사진마다 `PHOTO · 브랜드`. 레이아웃은 `pipeline/assets/ref_sankit_press_layout.html`(SANKIT 프레스 사진 카드)을 참고한다.
- 사진 없이 글자 카드로 만들어도 되는 것: 슬롯3의 역사·기술 해설, GUIDE(공연·페스티벌), THIS WEEK, 단신(슬롯4·5). 이때도 아래 '카드 구성의 변화'를 지킨다.
- 쇼핑몰·리뷰 매체·SNS·위키 사진은 절대 쓰지 않는다. 아티스트·인물 사진, 공연 포스터도 쓰지 않는다. 제품 모양을 그림으로 흉내 내지 않는다.

## 카드 구성의 변화 (단조로움 금지)
- **루페는 한 게시물에 최대 2장**(표지 포함). 나머지 장은 사진 카드, 큰 숫자 카드, 사양·비교 표 카드, 인용·한 문장 카드 등으로 바꾼다.
- 6장이 모두 같은 틀(흐린 모노 글자 배경 + 루페 + 제목 + 본문)이면 안 된다. 렌더 후 미리보기를 보고 같은 모양이 3장 이상 이어지면 고친다.
- 루페로 확대하는 대상은 숫자·값처럼 '확대할 이유가 있는 것'만. 'FRONT', 'STACK' 같은 단어 하나를 확대하는 건 피한다.
- 표지는 사진이 있으면 사진이 주인공(위 60% 사진 + 아래 제목), 없을 때만 루페 표지.

## 카드 형식 (B-3 루페, 6장)
- 기준 예시: `pipeline/assets/example_kit001.html` — CSS와 루페 스크립트(.lens / .plate / .tg)를 그대로 가져다 쓴다. 각 카드는 `class="card"`.
- 6장 구성: 01 표지(루페 + 키커 + 제목) / 02 왜 지금 / 03 여기를 보세요 ① / 04 여기를 보세요 ② / 05 솔직한 숫자(어두운 카드, 한계·단점 하나) / 06 MUKIT NOTE(관점 + 사양 표 + SOURCE).
- 상단: `MU`(먹) + `KIT`(오렌지) 워드마크와 `뮤킷`, 오른쪽 `KIT 0NN`. 하단: `GEAR / 분야` · `@MUKITMAG`.
- 색: 바탕 #F2EFE8, 먹 #151515, 오렌지 #D9481F, 보조 회색 #8B877F. 글꼴: Noto Sans CJK KR, 숫자·라벨은 DejaVu Sans Mono.
- 루페 원칙: 원은 무언가를 확대할 때만. 확대 대상은 그 기사의 결정적 숫자·단어 하나(`.tg`). 장식용 원·도형 금지.
- 이유 없는 빈칸 채우기 문구 금지, 감성 과잉 금지, 한쪽에 몰린 글자 배치 금지. 줄바꿈은 `<br>`로 직접 끊는다.

## 글쓰기 (운영자 말투)
- 한국어 평서체("~다."), 짧고 담백하게. 직접 듣고 만져 본 사람의 시선, 과장 없이 솔직한 한마디.
- 뉴스 받아쓰기 금지. 06 MUKIT NOTE에 반드시 관점 한 줄: "이게 왜 흥미로운가 / 누구에게 맞는가".
- 05 솔직한 숫자는 리뷰·사양에서 확인된 한계만 쓴다. 근거가 엇갈리면 그 장을 다른 사실로 바꾼다.
- 가격: 해외가는 "미국/유럽 판매가" 명시. 국내가는 확인된 경우만.
- 캡션 구조: `KIT 0NN · 영문 제목` / 한 줄 제목 / 본문 2~3단락 / 사양·가격 줄 / `Source: …` / 브랜드 @계정 / 해시태그 8~10개(#MUKIT #뮤킷 포함).
- reel_caption: 2문장 + "자세한 이야기는 피드의 KIT 0NN에서." + 해시태그 5~6개.

## 민감 브랜드·이해관계 (필수)
- 운영자가 따로 정한 브랜드 규칙은 예약 작업 지시문에 있다. 반드시 그 규칙을 따른다.
- 서로 경쟁하는 브랜드를 비교하거나 깎아내리지 않는다. 같은 날 같은 브랜드 2개 이상 금지, 한 주에 같은 브랜드 3회 이상 금지.
- 사고·소송·정치·선정적 주제, 협찬·광고 콘텐츠는 자동 운영에서 만들지 않는다.

## 운영자 콘텐츠 (하루 1개, 운영자 사진)
- 운영자 지시(2026-11-03): 운영자가 직접 사진을 보내 올리고 싶은 콘텐츠를 하루 1개씩 올린다. 그날 자동 기사 하나를 자연스럽게 빼서 하루 총 5개를 유지한다.
- 운영자 콘텐츠는 대화 중인 세션이 만든다(직접 찍은 사진 기준 예시 형식, 카드 + 릴스 + 스토리). 자동 제작 세션은 만들지 않는다.
- 자리 잡기:
  - 운영자가 '바로'라고 하면 즉시 게시하고, 그날 아직 게시되지 않은 슬롯 중 **단신(슬롯4·5)을 먼저** 뺀다(없으면 다음 미게시 슬롯). 뺀 슬롯 폴더는 `queue/YYYY-MM-DD/slotN` → `queue/_dropped/YYYY-MM-DD-slotN`으로 옮긴다.
  - 시간을 정하거나 '예약'이면 그 시간에 맞는 슬롯 폴더를 운영자 콘텐츠로 교체한다(기존 자동 기사는 `_dropped`로).
  - 다음 날 이후 날짜로 미리 받으면 `queue/YYYY-MM-DD/slotN/`에 먼저 만들어 둔다. 자동 제작 세션은 이미 post.json이 있는 슬롯을 건너뛰므로, 그날은 나머지 4개만 만든다.
- LOG에는 제목 앞에 `[OWNER]`를 붙인다. 자동 제작 세션은 그날 이미 `[OWNER]`가 있으면 자기 몫을 4개로 줄인다.
